# Architecture — drwil

As of 2026-10-23. Map of the repository: what lives where. Kept up to date in the same commit as the code it describes, which the `architecture-map` check enforces (QUA-040): every file of `packages/drwil/src/`, `.githooks/` and `outils/` (tests excluded) is cited here. It points to the documents that go into detail, without copying them.

## What drwil does

drwil is a **governance kit for AI-assisted development**. In a software project, it installs instructions for the agents (Claude Code, Codex, Cursor, Copilot, Gemini), workstream briefs, a contract registry and checks replayed at commit, at push and in CI; `drwil verify` then says, with evidence, whether the work is verified. Every workstream leaves its non-regression behind: its acceptance criteria become contracts of the registry, replayed everywhere afterwards. For whom: a team, or a single person, who has agents do the work and wants to keep the decision and the proof.

This repository has two roles (QUA-018): **drwil the deliverable**, the npm package `packages/drwil` and its template; **drwil the repository**, this project, which applies its own governance to itself. The repository's working language is French (briefs, contracts, journal, commits); what a visitor reads first (README, INSTALL, this map, changelog) is in English.

## Stack

Node.js 22 or later (package `engines`; CI on Node 22 and 24), TypeScript for the CLI, dependency-free JavaScript (`.githooks/*.mjs` modules) for the hooks. A single runtime dependency: `commander`.

## The checks: `.githooks/`

- `.githooks/engine.mjs`: the single check engine, shared by the hooks and `drwil verify` (its names and messages in `.githooks/engine-texts.mjs`, the main-branch check in `.githooks/engine-branch.mjs`, the temporary folders of a pass in `.githooks/engine-pass.mjs`, the launching of the commands and the shared build in `.githooks/engine-launch.mjs`); `.githooks/run-checks.mjs` runs it at commit (`pre-commit`), at push (`pre-push`) and in CI (its messages in `.githooks/run-checks-texts.mjs`, the verdicts it leaves and reuses in `.githooks/run-checks-verdicts.mjs`); `.githooks/glob.mjs` matches the checks' paths, both for deferring at commit and for CI coverage.
- `.githooks/fingerprints.mjs`: the fingerprints of what the checks judge (the whole tree, and each check's own files for per-check reuse, QUA-141), re-exported by `.githooks/engine.mjs`.
- Baseline checks: `.githooks/check-docs.mjs` (cited docs and contracts; its messages in `.githooks/check-docs-texts.mjs`, the workstream and scope checks in `.githooks/check-docs-workstreams.mjs`, the path test in `.githooks/check-docs-paths.mjs`), `.githooks/doc-coherence.mjs` (with `.githooks/doc-coherence-texts.mjs` for its messages and `.githooks/doc-coherence-fixes.mjs` for the line rewrites; index, brief and code coherence rules, shared by check-docs at each commit and by closing), `.githooks/skill-headers.mjs` (skill headers read in strict YAML, QUA-062), `.githooks/check-contract-tests.mjs` (tests cited by the contracts, QUA-029), `.githooks/check-architecture.mjs` (this map, QUA-040), `.githooks/scope-gate.mjs` (scope gate of the active brief; its messages in `.githooks/scope-gate-texts.mjs`, the merge resolution in `.githooks/scope-gate-merge.mjs`), `.githooks/check-control-coverage.mjs` (CI coverage of each check; the CI jobs read in `.githooks/check-control-coverage-jobs.mjs`).
- Governance: `.githooks/state.mjs` (state, transitions, starting and queueing workstreams, reopening a closed workstream whose pull request revealed a defect, QUA-116; reads the briefs through `.githooks/briefs.mjs` (with `.githooks/briefs-criteria.mjs` for acceptance criteria and declared contracts, `.githooks/briefs-intents.mjs` for the brief → intent loop `.githooks/briefs-overlap.mjs` for the overlap of two scopes and `.githooks/briefs-order.mjs` for the order of the poll, that of the index's "Fiches cadrées" section, QUA-160), the state's shape and its reader in `.githooks/state-validate.mjs`, the verify evidence in `.githooks/state-evidence.mjs`, the transitions in `.githooks/state-transitions.mjs`, the reopening in `.githooks/state-reopen.mjs`, the acceptance of a brief's criteria by the human at start, read back at closing, in `.githooks/state-acceptance.mjs` (QUA-174, QUA-175), the lots of a brief with several increments (`.githooks/briefs-lots.mjs` reads the « **Lot N — title** [IA|human] » bullets, `.githooks/state-lots.mjs` holds the current lot and the lots done in a local file of `.drwil/`, `.githooks/state-cli-lots.mjs` is `state.mjs lot` and `lot next`: one fresh subagent per lot, one closing, QUA-166 to QUA-171), formats through `.githooks/state-texts.mjs` (context texts in `.githooks/state-context-texts.mjs`, transition messages in `.githooks/state-messages.mjs` with `.githooks/state-messages-fr.mjs` and `.githooks/state-messages-en.mjs`), command line in `.githooks/state-cli.mjs`, including the JSON modes `copilot-start` and `copilot-message` that Copilot CLI reads, QUA-065, and `gemini-start` and `gemini-message` that Gemini CLI reads, QUA-067), `.githooks/scope.mjs` (briefs' scope block, declared copies), `.githooks/contracts.mjs` (registry reading;
